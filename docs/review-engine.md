# 문장 심사 엔진 2.0

버전 1.1.0 / 2026-10-15. 기존 화면과 서식, 사건 전이 규칙을 유지하면서 새 심사의 문장 해석과 의견 작성을 변경했다. 생성형 AI, 학습 모델, 외부 분석 API, 새 런타임 의존성을 사용하지 않는다.

## 입력을 읽는 방법

`src/domain/analysis.ts`는 해야 할 일·신청 사유·부연 소명·보완·이의신청의 출처를 구분한다. 문장과 대조절을 나누고 다음 항목을 식별한다.

| 항목 | 읽는 내용 |
| --- | --- |
| 진행 상태 | 착수 전, 진행 중, 자료 확보, 남은 본문, 최종 검토, 전체 완료 진술 |
| 사유 | 피로·수면 부족·신체 불편·장시간 작업·의욕·여가·일정 중복·외부 자료/응답 대기·접속 장애·부담 |
| 표현의 방향 | 긍정 진술과 부정, 제삼자의 상태, 인용 예시, 가정, 회복·장애 해소, 뒤에 명시한 부정 |
| 시간 | 오늘/내일 이후/기한 없음, 숫자·한글 상대시간, 시각, 휴식 종료·외부 응답 등 복귀 계기 |
| 실행계획 | 시점 또는 계기 + 대상업무의 구체적 행동 + 이행 의사. 세 요소를 함께 검토 |

모든 사실 항목은 입력 출처와 해당 부분의 인용문을 보존한다. 드롭다운의 사유 이름보다 본문의 실제 사정을 우선한다. 업무란의 단순한 “미루고 싶다”는 신청 원인으로 대체하지 않는다. 입력이 길다는 이유로 사실이나 실행계획을 인정하지 않는다.

“피곤하지 않다”, “의욕이 없는 건 아니다”, “게임을 하려는 게 아니다”를 해당 사정의 긍정 진술로 사용하지 않는다. “잠을 못 잤다”는 수면 부족으로 읽는다. “10분 뒤 작성할 계획이 없다”나 계획·시간 등의 단어 나열은 복귀 계획으로 사용하지 않는다.

## 판단과 문장 구성

1. 기한의 모순, 불명확한 사유, 신청시간보다 늦은 복귀, 이미 완료한 대상업무 등은 무엇을 밝혀야 하는지 지정하여 보완을 요구한다. 한 번 보완한 뒤에도 해소되지 않으면 최종 불승인한다.
2. 오늘 마감과 하루 유예가 충돌하면 엄격 심사에서 불승인한다. 준비 완료 여부, 피로, 외부 대기, 여가 희망 등에 따라 앞의 사실 판단은 각각 다르게 쓴다.
3. 정해진 기한이 없고 10~30분의 단시간이며, 구체적 복귀 계획과 휴식·준비의 사정이 있고 외부 대기 조건이 남지 않으면 승인할 수 있다.
4. 단순한 의욕·여가 희망만으로 장시간 유예를 요구하고 복귀 계획도 없으면 엄격 심사에서 불승인한다. 그 외에는 확인된 사정과 실행조건을 함께 검토해 조건부 승인한다.
5. 의견은 제출한 진술 → 그 사정이 착수에 미치는 영향 → 요청시간·실제 기한과의 관계 → 처분 순서로 구성한다. 권고하는 첫 행동도 이미 끝낸 단계와 실제 복귀 계획에 맞춘다.

본문에서 분명하게 제시한 기한은 ‘불명’ 선택을 보충할 수 있다. 선택한 기한과 본문이 충돌하면 임의로 유리한 쪽을 택하지 않는다. 보완·이의신청에서 명시적으로 정정하거나 확인 결과를 밝힌 경우에는 새로운 진술을 반영하되 최초 신청서를 수정하지 않는다. 외부 기한이 객관적으로 확인되었다고 표현하지 않는다.

## 예시

입력: 오늘 마감 / 하루 / 엄격 심사

> 자료는 다 찾았고 본문만 남았다. 게임 좀 하다가 내일 쓰고 싶다.

심사 의견에는 “남은 대상업무”, “여가 활동 우선 희망”, “오늘의 마감기한과 하루 유예 요청이 충돌함”이 반영된다. 권고는 안내문부터 다시 읽으라는 고정 문구 대신 **남은 본문의 첫 문장 작성**으로 바뀐다.

입력: 기한 없음 / 10분

> 졸려서 쉰다. 10분 뒤 본문을 쓰겠다.

짧은 문장이지만 현재 피로와 복귀 시점·행동이 식별되므로 승인할 수 있다. 반대로 단어를 길게 반복한 소명은 구체적인 사정으로 인정하지 않는다.

## 보완·이의신청과 기록

이의신청은 최초 분석과 새로운 소명을 비교한다. 같은 계획을 숫자/한글이나 비슷한 말로 다시 적는 것만으로 처분을 바꾸지 않는다. 새로운 첫 행동·복귀 시점이나 진행 상태·장애 해소가 있어야 하며, 실행 가능한 계획이 필요하다. 오늘 마감·하루 요청의 재심사에서는 30분 이내의 새 착수 계획으로 범위를 좁히는 경우만 조건부 변경할 수 있다. 이때 F-07에도 좁아진 인정 범위를 기록하며 하루 전체를 승인했다고 표시하지 않는다.

- 새 결정: `review-engine/2.0`, 근거: `sentence-rules/2.0`.
- 과거 `review-engine/1.0` 결정과 문서는 스냅샷을 그대로 열람·복원한다.
- v1.0과 v2.0이 섞인 백업도 왕복 복원한다. 재심사는 새 엔진으로 하되 원처분과 F-06을 덮어쓰지 않는다.
- 같은 입력·같은 결정 시각은 같은 결과다. 임의 점수·난수·문자 수에 따른 판정을 사용하지 않는다.
- 결과 화면의 ‘신청내용에서 검토한 사항’에서 문장 근거와 검토 내용을 확인할 수 있다.

## 해석의 한계

이 엔진은 정해진 일상업무 영역의 어휘·구문·시간 규칙을 다룬다. 형태소 분석기나 범용 언어 이해 모델은 아니다. 복잡한 이중부정·반어·은유·여러 사람의 발언·정확한 달력 시각 계산 등은 모두 해결하지 않는다. 인용이나 가정으로 분류되어 실제 사정이 누락될 수도 있다. 인식되지 않은 내용은 소명을 요청하며, 사용자의 진술을 외부 증빙이나 진단으로 바꾸지 않는다.

자연어 대비 사례는 `tests/analysis.test.ts`, 사건·원처분 보존은 `tests/review.test.ts`, 신구 백업 복원은 `tests/storage.test.ts`, 실제 화면과 PDF 흐름은 `tests/e2e/portal.spec.ts`에서 검증한다.

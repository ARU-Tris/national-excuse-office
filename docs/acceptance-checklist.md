`npm test`: **112개 통과** (문장 대비 사례 91개, 사건 전이·기존 문서 보존 12개, 저장·신구 백업 복원 9개). TypeScript 및 Vite 프로덕션 빌드 통과.

프로덕션 프리뷰에서 **13개 E2E 시나리오 검증**: 기존 10개와 문장별 심사·근거 펼침·모바일 결과, 부정된 피로의 오인 방지, 기한 충돌 보완·정정 3개. 전체 실행의 12개 통과 후 발견한 결과 화면 가로 넘침을 수정하고 해당 시나리오를 재실행하여 통과했다. 새 문장 심사와 PDF 로딩 중 외부 요청이 없는 것도 확인했다.

실제 사건에서 **12개 PDF / 15페이지** 생성 후 구조·한글/한자 추출·글꼴 내장·A4·텍스트 범위·모든 페이지 푸터 검사를 통과했다. Poppler 렌더링으로 확인했다. F-01~F-08 대표 문서는 각 1페이지, 추가 소명과 상세 의견을 포함한 F-09는 2페이지, 장문 F-06은 3페이지이다. 별도 문장별 불승인 F-06과 인정 범위를 좁힌 재심사 승인 F-07도 각 1페이지로 확인했다. 최종 안내와 관인을 함께 배치하여 관인 단독 페이지를 방지한다.

새 엔진은 새 심사부터 적용하며, 기존 민원을 열어도 기존 결정을 다시 계산하지 않는다. 기존 대표 디자인 샘플과 원본 `국립핑계관리청.md`는 보존했다. 물리적 프린터·별도 브라우저·실제 화면 읽기 제품의 검증 범위는 아래 기록과 같다.

## 자동화 결과

프로덕션 `npm run preview`의 `/national-excuse-office/` 경로에서 **10개 E2E 시나리오 통과** (전체 9개 실행 후 키보드 전용 시나리오 추가 실행, 최종 모바일 재확인):

2. 기한 없음·10분·구체적 사유 승인 및 F-07
3. 보완요구 → 1회 보완 → 최종 처분 및 F-03 보존
4. 긴 한글/한자/영문/숫자 입력, PDF 페이지 추가, HTML 문자 비실행
5. 390px 모바일, 가로 넘침 없음, 미완성 신청서 임시저장 복원, 외부 요청 없음
6. 삭제 전 확인, 취소 보존, 손상된 백업 차단
7. IndexedDB 차단 안내 및 접수 지속
8. 글꼴 로딩 실패 시 빈 PDF 차단·한글 오류 안내·재시도 복구
9. 이미 로드한 신청·심사 코드를 네트워크 연결 없이 실행

10. 키보드 Tab/Space/Enter만으로 신청서 입력·필수 동의·접수 완료 확인

키보드 흐름은 별도 테스트로 통과했다. 실제 스크린리더 제품을 통한 음성 검증은 수행하지 않았다.
